## 2. LOCAL DEVELOPMENT SETUP

### Prerequisites
- Node.js (LTS version)
- Expo CLI (npm install -g expo-cli if needed)
- EAS CLI (npm install -g eas-cli if needed)
- iOS Simulator via Xcode (for local iOS testing)
- Apple Developer account (for builds and TestFlight)

### Starting Local Dev
```bash
# Install dependencies (if fresh clone or after branch switch)
npm install

# Start Metro bundler with clean cache
npx expo start -c

# Run on iOS simulator
npm run ios

# Run on Android emulator
npm run android

# Run in web browser
npm run web
```

### If Local Dev Will Not Start
```bash
# Step 1: Check for issues
npx expo doctor

# Step 2: Clear cache and restart
npx expo start -c

# Step 3: If still broken, check BUILD_FIX_LOG.md for known fixes

# Step 4 (DESTRUCTIVE — ASK KP FIRST): Nuclear reset
rm -rf node_modules package-lock.json
npm install
npx expo start -c
```

## 4. EXPO CONFIGURATION

### app.json (Static — rarely changes)
Controls:
- name, slug — app identity
- scheme — deep linking
- icon, splash — visual assets
- ios.bundleIdentifier — com.byred.authentichadith
- ios.buildNumber — increment for each App Store submission
- plugins — Expo plugins

### app.config.js (Dynamic — environment-based)
Controls:
- Values that change per environment (dev/staging/prod)
- EXPO_PUBLIC_ variable injection
- Anything computed at build time

### Rules
- Static metadata goes in app.json
- Dynamic/environment values go in app.config.js
- Never put secrets in app.json (it is committed to git)
- Bump ios.buildNumber in app.json before every new App Store/TestFlight upload

## 4b. PRE-PREBUILD CONFIG CHECKLIST

Before running `npx expo prebuild --clean` or any EAS build (always KP-approved), verify in `app.json`:

- [ ] Every entry in `expo.plugins` is verified to ship a real config plugin (SYSTEM_RULES Rule 021). For each entry, at least ONE of the following must be true:
  - `ls node_modules/<package>/app.plugin.js` succeeds
  - `node -e "console.log(require('./node_modules/<package>/package.json').expo)"` returns a non-undefined value
  - The package documentation explicitly says "add to expo.plugins" (link captured in BUILD_FIX_LOG)
- [ ] **Adding a package to `expo.plugins` without one of the above signals is forbidden.** Packages that autolink (e.g. `react-native-purchases`) must NOT be added to `expo.plugins`. Their iOS capabilities are enabled externally (Apple Developer portal, App Store Connect) or via manual `infoPlist` keys.
- [ ] `expo.name` matches the marketing name on the App Store listing
- [ ] `expo.ios.bundleIdentifier` is `com.byred.authentichadith`
- [ ] `expo.ios.buildNumber` is current (or rely on EAS `autoIncrement` for production)
- [ ] `expo.ios.infoPlist.CFBundleDisplayName` matches user-facing name ("Authentic Hadith")
- [ ] `expo.ios.infoPlist.ITSAppUsesNonExemptEncryption` is set (false unless encryption used)
- [ ] No orphan capabilities will result from removed plugins (cross-check existing `ios/<App>/<App>.entitlements`)

**Mandatory gate before commit on any `expo.plugins` change:**

```bash
node -e "JSON.parse(require('fs').readFileSync('app.json'))"   # JSON validity
npx expo config --json > /dev/null                              # Plugin resolution
echo "exit: $?"                                                 # Must be 0
```

A non-zero exit code means a plugin entry is invalid. Revert before committing. This gate exists because FIX-026 was committed and pushed without running it, which broke every EAS build until FIX-027 reverted the bad entry.

After prebuild completes, verify:

- [ ] `ios/<App>/<App>.entitlements` contains expected capabilities and nothing more
- [ ] `ios/<App>/Info.plist` `CFBundleDisplayName` matches the configured value
- [ ] No `aps-environment` unless push is intentionally shipping
- [ ] In-App Purchase capability is present if RevenueCat is in use AND the Apple Developer portal toggle is ON for the bundle ID. If the entitlement is missing, the fix is in the Apple Developer portal, not in `expo.plugins`.

## 5. iOS BUILD PROCESS

### Preflight: UTF-8 locale (SYSTEM_RULES Rule 022)

Every shell that runs `pod install`, `npx expo run:ios`, `npx expo prebuild`, or a local EAS iOS build must have a UTF-8 locale exported. CocoaPods crashes with a Ruby encoding error if `LANG` and `LC_ALL` are unset or `C`.

```bash
# Run once per shell, or add to ~/.zshrc for permanence
export LANG=en_US.UTF-8
export LC_ALL=en_US.UTF-8

# Verify before continuing
locale | grep -E "LANG|LC_ALL"
# Expect: LANG=en_US.UTF-8, LC_ALL=en_US.UTF-8 (not empty, not "C")
```

If `pod --version` prints `WARNING: CocoaPods requires your terminal to be using UTF-8 encoding`, stop and fix the locale before any build command.

### Build Profiles (eas.json)
| Profile | Purpose | Distribution | When to Use |
|---------|---------|-------------|-------------|
| development | Local dev builds | Internal | Testing with dev client |
| preview | TestFlight builds | Internal | Beta testing before release |
| production | App Store builds | Store | Final release to App Store |

### Running a Build
```bash
# Preview build (TestFlight)
npx eas build --platform ios --profile preview

# Production build (App Store)
npx eas build --platform ios --profile production

# Check build status
npx eas build:list
```

### Pre-Build Checklist
- [ ] ERROR_REPORT.md status is 🟢 (no active bugs)
- [ ] All TypeScript errors resolved (npx tsc --noEmit)
- [ ] Environment variables set correctly in .env.local
- [ ] ios.buildNumber incremented in app.json (if uploading to App Store Connect)
- [ ] npx expo doctor shows no critical issues
- [ ] Tested locally on iOS simulator
- [ ] No uncommitted changes that should be included

### Build Fails?
```
1. Read the EAS build logs (link provided in terminal output)
2. Search BUILD_FIX_LOG.md for the error message
3. Common causes:
   - Dependency version mismatch → npx expo doctor
   - Provisioning profile issue → check Apple Developer portal
   - Native module error → may need npx expo prebuild --clean (ASK KP)
   - Bundle ID mismatch → check app.json ios.bundleIdentifier
4. Log the fix to BUILD_FIX_LOG.md after resolving
```

## 6. TESTFLIGHT PROCESS

### After Successful Build
```bash
npx eas submit --platform ios
```

### Steps
1. Build completes on EAS — download link provided
2. Run npx eas submit --platform ios
3. Select the build to submit
4. App appears in App Store Connect — TestFlight tab
5. Wait for Apple processing (usually 10-30 minutes)
6. If compliance questions appear — answer them in App Store Connect
7. App becomes available to internal testers automatically
8. For external testers — submit for Beta App Review

## 8. COMMON ERRORS AND FIXES

> Detailed fixes with full context are in BUILD_FIX_LOG.md.

| Error | Likely Cause | Quick Fix |
|-------|-------------|-----------|
| Metro bundler failed to start | Cache corruption | npx expo start -c |
| Unable to resolve module | Missing dependency | npx expo install [package] |
| TypeError: null is not an object | Uninitialized state/context | Check component mounting order |
| Invariant Violation | React Native component error | Check import paths and component props |
| EAS build failed | Config or dependency issue | Read EAS build logs, run npx expo doctor |
| Provisioning profile not found | Apple Developer config | Check certificates in Apple Developer portal |
| EXPO_PUBLIC_ var undefined | Missing from .env or not prefixed | Check .env.local, restart Metro |
| Supabase connection failed | Wrong URL/key or network issue | Check .env.local, check Supabase dashboard |
| RevenueCat error | Wrong API key or entitlement | Check .env.local, check RevenueCat dashboard |
| TypeScript error | Type mismatch | npx tsc --noEmit for full error list |
| pod install failed | iOS native dependency issue | npx expo prebuild --clean (ASK KP) |
| Groq/AI SDK error | Missing API key, model issue | Check .env.local, check lib/ AI config |
| Hadith detail "not found" | FK join on hadiths table | Remove FK joins, use .select('*') — see SYSTEM_RULES Rule 010 |
| Search returns zero results | Wrong column name in filter | Verify column names: english_text, arabic_text, narrator — see Rule 011 |
| Screen shows "undefined" | DB column name mismatch | Check actual column name (e.g. name_en not name) — see Rule 001 |
| Achievements/badges crash | Alias columns missing from DB | Verify alias columns exist: xp, hadiths_read, name, description |
| Chapter shows ALL hadiths | No filter on hadiths query | Use 3-hop chain: chapter→book→collection→hadiths — see Rule 010 |
